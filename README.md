# Noema · Research Lab v0.1

Самостоятельная симулируемая лаборатория покрытий. Человек и внешний агент проводят опыты через один HTTP API, фиксируют предсказания, сохраняют рецепты и проверяют их на свежем материале. LLM и харнес для запуска не нужны.

## Запуск

Python 3.12+, локальный однопроцессный сервис:

```sh
./run.sh
```

Открыть http://127.0.0.1:8765 и вставить `token` из `credentials-local.json`. Этот файл и БД исключены из Git. UI уже обслуживается сервером; Node.js, сборка frontend и отдельный frontend-процесс не нужны.

Кнопка **«Начать новую попытку»** создаёт чистое прохождение того же сценария: 100 credits и полный запас материала. Предыдущая попытка сохраняется; переключатель в шапке позволяет вернуться к ней в текущей браузерной сессии. Физического удаления или обнуления прежнего run нет.

`run.sh` запускает публичный сервис на 8765 и отдельный локальный контроль человека на 8766. Контроль требует локальную HttpOnly cookie и токен текущей попытки, проверяет Origin и сохраняет ключ безопасного повтора. Participant API и SDK не предоставляют создание попыток. Не открывайте порт 8766 или локальный управляющий ключ worker харнеса. При запуске только публичного uvicorn/Docker кнопка отсутствует.

При ручной установке:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/python -m lab.admin create > credentials-local.json
.venv/bin/python -m lab.local
```

OpenAPI: `/api/openapi.json`. Swagger: `/api/docs`. Публичный контракт: [PUBLIC_API.md](PUBLIC_API.md). `Authorization: Bearer <token>`, все POST требуют `Idempotency-Key`. UI хранит токен только в текущей браузерной сессии и восстанавливает заметки, измерения и журнал из сервера.

## Работа

1. Прочитать заказ и критерии. Отобрать порции, используя поле номинальной массы.
2. Выбрать порцию. Измерить контроль, обработать экспериментальную порцию и сравнить наблюдения.
3. По желанию записать предсказание до измерения. Старые наблюдения после обработки помечаются как устаревшие.
4. Записать гипотезу в блокнот. Составить линейный рецепт в редакторе.
5. Сохранить рецепт и отправить на независимую проверку. Отдельно видны стоимость исследования, проверок и производственного рецепта.

В UI нет готовых решений. Показания появляются только после измерения. Полный состав и параметры мира остаются на сервере.

## Durable операции и restart

SQLite WAL, схема `user_version=1`, транзакции `BEGIN IMMEDIATE`. Принятие резервирует credits, материал, образцы и прибор; worker сохраняет эффект, измерения и событие в одной транзакции. Публичные события — durable polling outbox. Accepted/running операции возобновляются при запуске. Crash до commit откатывает эффект; crash после commit оставляет готовый результат. Ошибка вычисления освобождает резерв.

Остановить сервер Ctrl+C и снова выполнить `./run.sh`, сохранив БД и credentials. Потеря HTTP-ответа восстанавливается повтором с прежним ключом или GET операции по ID. В UI есть кнопка безопасного повтора транспортного запроса. Физическое состояние не зависит от времени ожидания и GET-запросов.

MVP хранит каждый run как транзакционный JSON aggregate в SQLite через SQLAlchemy. Это осознанное ограничение пилота: один writer и один worker, короткие прохождения. Для высокой нагрузки потребуется нормализованное хранение, а не несколько uvicorn workers. Смена схемы должна сопровождаться миграцией; существующий v0.1 автоматически инициализируется.

## Локальный экспериментатор

```sh
.venv/bin/python -m lab.admin create --scenario S2 --label 'Участник'
.venv/bin/python -m lab.admin create --scenario S1 --paired
.venv/bin/python -m lab.admin create --scenario S4 --mode notified
.venv/bin/python -m lab.admin gain RUN_ID 0.5
.venv/bin/python -m lab.admin metrics RUN_ID
.venv/bin/python -m lab.admin export RUN_ID --output public-trace.json
.venv/bin/python -m lab.admin export RUN_ID --private --output private-trace.json
```

CLI изменения gain отказывает, пока есть accepted/running операции или проверка. В `notified` появляется сообщение об обслуживании без величины изменения; в `undisclosed` изменения видны только по новым наблюдениям. S4 начинается с baseline; момент изменения задаёт экспериментатор на границе фазы. Парные runs получают одинаковый профиль и общий private pair ID. До сравнения фиксировать версию движка, конфигурацию, порядок вмешательств и ресурсы. Приватный журнал хранит hash движка и первоначальную конфигурацию.

Admin не доступен через HTTP. Backend, database, конфигурацию, исходные спецификации и tests не монтировать в REPL испытуемого агента. Разработческий репозиторий не является пакетом знаний для участника.

## Публичный SDK и интеграция

```sh
.venv/bin/python scripts/export_public.py
# Передать только public/participant.zip и изолированный participant-token.
# В распакованном публичном пакете:
pip install .
LAB_URL=http://127.0.0.1:8765 LAB_TOKEN=... python -m sdk.example
LAB_URL=http://127.0.0.1:8765 LAB_TOKEN=... python -m sdk.example OPERATION_ID
```

`sdk` — async HTTPX transport, публичные TypedDict, безопасный retry с сохранённым key, polling/resume. В нём нет импорта движка или стратегий. Харнес хранит свой operation mapping и последний event sequence. Лаборатория не использует внутренние сущности харнеса.

Проверка рецепта автоматически завершает охлаждение до 20 °C как verification overhead; эта служебная операция не входит в производственную цену шагов рецепта. Input/output масса при проверке рассчитывается на сервере. Verification-порции в журнале помечены и consumed, их нельзя повторно использовать.

## Docker

```sh
docker build -t noema-lab .
docker volume create noema-data
docker run --rm -v noema-data:/data noema-lab python -m lab.admin --db /data/laboratory.db create
docker run --rm -p 127.0.0.1:8765:8000 -v noema-data:/data noema-lab
```

Токен берётся из вывода команды create. `LAB_DB` задаёт путь БД, `LAB_DELAY` — транспортную задержку в секундах (по умолчанию .35). При публикации в сети нужен TLS reverse proxy; backend и административные файлы должны оставаться изолированными.


[Отчёт приёмки L01–L28](docs/ACCEPTANCE.md). Автоматический CI запускает тесты и сборку публичного контракта. Человеческий пилот здесь проводился разработчиком, знакомым со спецификацией; он проверяет интерфейс и достижимость, а не обучение. Агентный научный эксперимент и интеграция с настоящим харнесом остаются отдельной работой.
