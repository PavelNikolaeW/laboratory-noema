# Закрытая спецификация движка

НЕ передавать испытуемому агенту или участнику слепого сравнения. Документ содержит скрытые правила и решения. Чтение человеком отмечается как предварительное знание при оценке.

## 1. Состояние и численная семантика

Предложенная условная механика v0.1 не моделирует конкретные реальные вещества. Внутри образца хранятся:

```text
a0_g — масса неактивированного компонента A
a1_g — масса активированного компонента A
b_g  — масса компонента B
i_g  — масса примеси
temperature_c
revision, status, provenance
```

Полная масса M = a0 + a1 + b + i. Нельзя хранить только один флаг фазы: после смешивания активированной и исходной порций фаза бывает частичной. Разложение a0/a1 делает смесь однозначной.

Все количества неотрицательны, M > 0, T в [20, 200]. Decimal precision 28, на внутренних шагах не округлять публичным форматом. Публичные масса/температура: 6 знаков, отклик: 6 знаков, ROUND_HALF_EVEN. Инварианты массы проверять с допуском 1e-12 г на внутреннем Decimal; абсолютную математическую точность при делении не обещать. Остатки при split/separate вычислять вычитанием исходного количества, чтобы не накапливать независимые округления.

Минимальная порция после split/separate 0.001 г. Если операция создала бы выход меньше этого порога, команда отвергается до принятия по общей массе выхода; формулировка ошибки не раскрывает состав. Для отдельной скрытой смеси отказ тоже является наблюдением, это допустимо; не возвращать вычисленные компонентные значения.

Состояние партии: начальные доли a0/a1/b/i, T=20, остаток массы. obtain создаёт порцию с теми же долями; запас убывает на номинальную массу. Команда reference выдаёт особый сертифицированный стандарт, не продуктовую партию.

## 2. Переходы

### Нагрев

```text
E = 10 * heater_gain * power * duration
T_new = min(200, T + E / M)
if T_new >= activation_threshold:
    a1_new = a1 + a0
    a0_new = 0
else:
    a1_new = a1
    a0_new = a0
```

Базовый heater_gain=1, activation_threshold=70. Условная теплоёмкость на единицу массы одинакова для всех компонентов. Коэффициент 10 связывает безразмерные параметры прибора с единицами модельной температуры; не выдавать за реальные ватты/секунды. В публичном паспорте power и duration названы уровнями и тактами.

Нагрев не меняет массу. Активация необратима в v0.1. Это создаёт зависимость от истории: холодные образцы одинаковой массы могут иметь разные свойства и по-разному разделяться. Saturation температуры не считается отказом.

### Охлаждение

T_new = min(T, requested_target). Команда никогда не нагревает. a0/a1 и масса неизменны; пассивного остывания между командами нет.

### Разделение порции

split(f): первый выход содержит f каждого компонента, второй — исходное минус первый; обе температуры равны исходной. Исходник consumed. Обе дочерние порции имеют собственные ID и revision=1.

### Сепарация

selective создаёт selected и remainder:

| Компонент | Доля в selected |
| --- | --- |
| a0 | 0.50 |
| a1 | 0.90 |
| b | 0.40 |
| i | 0.20 |

remainder для каждого компонента = вход − selected. Температуры сохраняются. Исходник consumed. Названия выходов не раскрывают чистоту, предполагаемый состав или предпочтительность для заказа.

### Смешивание

Два различных available образца: компоненты складываются, T_new = (M1*T1+M2*T2)/(M1+M2). После выравнивания температуры применяется тот же порог активации: если T_new >= threshold, весь a0 смеси переходит в a1. В противном случае уже активированное количество сохраняется. Это устраняет противоречие между горячей смесью и нагревом.

Оба входа consumed, результат новый. Смешивание не «омолаживает» историю активации. Происхождение — DAG; новый ID не маскирует использование стандарта или чужой партии.

## 3. Измерения

```text
mass = M
temperature = T
true_response = clamp(100*(a0 + 1.3*a1 - i)/M, 0, 100)
observed_response = analyzer_gain * true_response + analyzer_offset
```

В базе analyzer_gain=1, offset=0, noise=0. Публичный паспорт отклика: условные единицы; не обещать строгий диапазон показаний 0–100 для будущего некалиброванного прибора. Базовое истинное свойство ограничено 0–100.

Температура напрямую не входит в response; влияет через историю активации. Это намеренно простая первая закономерность. Не делать произвольные тайные штрафы за неизвестную участнику семантику параметра.

Измерение не расходует/изменяет образец, revision образца не увеличивается. Observation фиксирует именно измеренный revision. Одинаковое измерение неизменного образца в базовом режиме воспроизводимо.

## 4. Контрольные материалы

Стандарт R-80: масса 10 г, сертифицированный отклик 80 при 20 °C; скрыто a0=8, a1=0, b=2, i=0. Сертификат описывает исходное состояние и теряет применимость после обработки. Его можно использовать для проверки анализатора или нагревателя через измерение температуры.

Стандарт имеет метку lineage `reference`, отличимую от партии. Нельзя выдать его за продукт заказа, смешать со стандартом и получить зачтённый выход. Основная проверка рецепта сама создаёт порции целевой партии, поэтому подмена ID не работает. Исследовательское mix со стандартом допустимо, но потомки сохраняют происхождение.

## 5. Сценарии и эталонные проверки достижимости

Это development fixtures; evaluation seeds/партии не должны совпадать со всем тренировочным набором. Пилот: исследовательский бюджет 100 credits, запас каждой рабочей партии 200 г, validation_repeats=2, validation_cost=10 credits, отдельный verification reserve ≥ 40 г. Числа конфигурационные, до научного сравнения ещё калибруются.

### S1. Базовый заказ

Партия: доли a0=0.60, a1=0, b=0.35, i=0.05. Порция 10 г. Критерии: response ≥70, yield ≥0.80, recipe_credits ≤15.

- Исходный отклик 55.
- heat(power=5,duration=12): T=80, активация.
- cool(20): T=20, отклик 73, yield=1.
- Стоимость рецепта: 2+60/60+1=4.

Рецепт выше — свидетельство достижимости, не единственное решение и не публичная подсказка.

### S2. Новая партия, иной маршрут

Доли a0=0.60, a1=0, b=0.20, i=0.20, M=10. Критерии: response ≥90, yield ≥0.60, recipe_credits ≤15.

- Один нагрев даёт отклик 58 — недостаточно.
- heat(5,12), cool(20), separate(selective), keep selected.
- selected: a1=5.4, b=0.8, i=0.4; M=6.6; yield=.66.
- true_response = min(100, 100*(1.3*5.4-.4)/6.6) = 100.
- Стоимость 7 credits. Обратный порядок может дать другой выход/качество; не все перестановки эквивалентны.

### S3. Перенос на другую массу

Та же композиция S1, но 20 г. Рецепт с power=5,duration=12 даёт T=50 и отклик55. Удвоенная подведённая энергия power=10,duration=12 даёт T=80 и отклик73. Пропорциональность массе требует нового предсказания, не просто запоминания одного рецепта.

### S4. Изменение оборудования

После независимого checkpoint в сценарии S1 heater_gain меняется с 1 на .5. Остальные параметры, партии и анализатор неизменны. Исходный рецепт даёт T=50, отклик55. heat(10,12) возвращает T=80, отклик73.

Изменение фиксируется в закрытом журнале между операциями, не во время принятой операции/validation. Публичное уведомление об обслуживании может присутствовать в режиме disclosed; в режиме undisclosed участник узнаёт только из наблюдений. Режим выбран до запуска и одинаков для сравниваемых участников. Изменение не запускается «когда агент догадался»; точка фазового перехода задаётся протоколом.

## 6. Учёт операций и восстановление

Принятие операции и резерв — одна транзакция. Worker берёт accepted/running, читает сохранённые входы и config snapshot. Commit перехода включает изменения образцов, Observation, финальную стоимость, статус и outbox event. Только один commit эффекта для operation_id, guarded status/version update.

Чистый расчёт можно повторить после аварии до commit. После commit повтор возвращает прежний результат. Детерминированные output IDs привязаны к operation_id либо атомарно сохранены; crash не создаёт новые порции поверх прежних.

Транспортное event delivery at-least-once. Outbox переживает restart; фильтры не пропускают закрытые события. В v0.1 processing-delay может быть 250–1000 мс для демонстрации асинхронности; он не влияет на физические переходы и стоимость. Порядок конкурирующих операций над общими ресурсами определяется транзакционной регистрацией; для baseline участник один.

## 7. Расширения после MVP

Вводить по одному: measurement noise; analyzer gain/offset drift; heater wear; очереди; сбой транспорта после commit; новая закономерность. Не смешивать всё в одном первом прогоне.

Для noise задать распределение и раздельные RNG потоки, сохранять результат каждого измерения и состояние/ключ RNG. Повтор одного operation_id не генерирует новый шум. Число polling-запросов не влияет на RNG. Исследовательская оценка должна учитывать интервалы/повторы, а не требовать точной формулы по шумным единичным данным.

Для изменения закона (например activation_threshold) создать отдельный протокол: фиксированная точка изменения, одинаковые условия сравнения и доступный различающий опыт. Не путать смену закона с новой партией или параметром устройства. Нельзя считать неизмеримый скрытый параметр обязательным к восстановлению.
