# Задание отдельному агенту-разработчику

Создай самостоятельный проект `research-lab` по этому пакету. Это симулируемая лаборатория материалов для экспериментов с человеком и LLM-агентом. Харнес разрабатывается параллельно в другом проекте: не реализуй его внутри лаборатории.

## Порядок чтения

1. SPEC.md — продукт и границы.
2. PUBLIC_API.md — контракт с UI и харнесом.
3. PRIVATE_ENGINE.md — закрытая механика и эталонные сценарии.
4. IMPLEMENTATION_AND_ACCEPTANCE.md — этапы и проверки.
5. EXPERIMENTS.md — исследовательское назначение.

## Приоритеты

1. Корректный детерминированный движок с сохранением массы и воспроизводимостью.
2. Durable API: идемпотентность, расходы, операции и восстановление.
3. Рабочий человеческий UI через тот же API.
4. Проверяемые рецепты и сценарий смены эффективности прибора.
5. Интеграция с харнесом только через публичный транспорт.

Числа и контракты — рабочая версия v0.1. Если найдёшь противоречие, зафиксируй его и внеси минимальное согласованное уточнение в документацию/тесты; не подменяй мир произвольной новой механикой. Не требуй дополнительных согласований для обычных обратимых решений по структуре кода.

## Важные ограничения

- Испытуемый агент не читает этот пакет целиком. Только PUBLIC_API.md, публичные схемы/SDK, операторские заявки и наблюдения.
- Изолируй engine/config/database/admin от REPL. Не передавай формулы в frontend bundle.
- Не используй реальную физику или случайность как оправдание несовпадения с заданными правилами.
- Не добавляй шум/износ в базовый профиль. Отдельное изменение heater_gain — контролируемый сценарий.
- Не делай live-физику зависимой от скорости человеческого чтения.
- Не выдавай готовый рецепт через API-подсказку и не прописывай решения по ID партии.
- Поддерживай обычные импорты публичного клиента, но не связывай код с внутренними файлами/онтологией харнеса.
- Все взаимодействия UI и агента подчиняются одним операциям, ценам и критериям.

## Первое полезное демо

Человек открывает UI, получает заказ, берёт две порции, измеряет контроль, обрабатывает вторую, сравнивает результаты, записывает предположение, сохраняет рецепт и получает независимую оценку. Затем backend перезапускается: состояние и результаты доступны. Тот же сценарий воспроизводится через клиент без браузера.

Перед сдачей приложи команды запуска, отчёт по L01–L28 и явный список нереализованного. Не заявляй, что LLM научилась, пока не проведён отдельный эксперимент.
